ROOT CAUSE #1: TRIPLE GAME DEFINITION (CRITICAL)
================================================================================

WHAT: Games are defined in THREE different places with different information

WHERE:
  1. CURRICULUM Dictionary (Lines 57-98 in app.py)
     └─ Defines skills per class
        Example: "Listening" → ["Listen & Do Adventure", "Story Time Quiz"]

  2. GAMES Dictionary (Lines 100-140 in app.py)
     └─ Defines games per skill (but NO FILE PATHS)
        Example: "Listening" → ["Listen & Do Adventure", "Story Time Quiz"]

  3. AVAILABLE_GAMES Dictionary (Lines 142-212 in app.py)
     └─ Maps game NAMES to FILE PATHS (only 46 games)
        Example: 'Listen & Do Adventure' → 'listen_do_adventure.html'

WHY IT'S A PROBLEM:
  ❌ Game exists in GAMES dict but not in AVAILABLE_GAMES
     → No file path defined
     → Flask can't find the file
     → Error: "Game file not created yet"

  ❌ Three sources of truth instead of one
     → Hard to maintain
     → Easy to get out of sync
     → Confusing for developers

  ❌ 120+ games listed but only 46 have file paths
     → 74+ games are "orphaned" (defined but unreachable)

EXAMPLE OF THE PROBLEM:
  Game: "Audio Story Sequencing"
  Status in GAMES dict: ✅ Listed
  Status in AVAILABLE_GAMES: ❌ NOT listed
  File exists?: ❌ NO
  Result: Can't access this game!

HOW TO FIX:
  → Use ONLY PostgreSQL database as single source of truth
  → Remove GAMES dictionary
  → Remove AVAILABLE_GAMES dictionary
  → Query database for all game information

ROOT CAUSE #5: API QUERIES WRONG DATA SOURCE (CRITICAL)
================================================================================

WHAT: The /api/available-games endpoint queries the EMPTY database instead
      of using the AVAILABLE_GAMES dictionary that actually has the data.

WHERE: Code Line 285-286 in app.py

CURRENT CODE (WRONG):
```python
@app.route('/api/available-games', methods=['GET'])
def get_available_games():
    games = db.session.query(Game).filter_by(is_active=True).all()
    # ↑ Queries EMPTY database!
    available_games = {g.name: g.file_path for g in games if g.file_path}
    # ↑ Result: empty dictionary!
    return jsonify({'available_games': available_games})
    # ↑ Returns empty list to client!
```

WHAT HAPPENS:
  1. Client: GET /api/available-games
  2. Flask: queries db.session.query(Game)...
  3. Database: returns [] (empty, no records)
  4. Flask: creates empty dict {}
  5. API returns: {"available_games": {}, "total_available": 0}
  6. Client sees: NO GAMES AVAILABLE

WHAT SHOULD HAPPEN:
  1. Client: GET /api/available-games
  2. Flask: should check database OR use AVAILABLE_GAMES dict
  3. Database: (still empty, but we check dict as fallback)
  4. Flask: uses AVAILABLE_GAMES dictionary
  5. API returns: {"available_games": {46 games}, "total_available": 46}
  6. Client sees: All 46 games available ✅

WHY IT'S A PROBLEM:
  ❌ Client apps relying on this API see no games
  ❌ Game lists show empty in any app using this endpoint
  ❌ Users think no games are available (not true!)
  ❌ Breaks any feature that lists available games

HOW TO FIX:
  Option A (Database First):
    → Seed database with all games
    → Keep using db.session.query()
    → Database will have data

  Option B (Dictionary Fallback):
    → Update API to check database
    → If empty, use AVAILABLE_GAMES dict
    → Temporary solution until database is seeded

  Option C (Hybrid):
    → Seed database (best solution)
    → API queries database
    → All features work correctly
